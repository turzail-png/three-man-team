# Upgrade Guide — v1.3.0
*Read by Arch. Execute every step in order. Do not skip.*

---

## What This Upgrade Adds

- `team-config.json` — single source of truth for team, models, version, file paths
- `project-standards.json` — coding standards and tooling constraints for Bob and Richard
- `handoff/build-recipe.json` — Bob's per-step execution plan
- `handoff/sprint-plan.json` — Arch's full sprint roadmap
- `handoff/known-gaps.json` — structured gap tracking
- `handoff-schema.json` — authoritative schema for all handoff files
- Review status upgraded: APPROVED / APPROVED WITH CONDITIONS / REJECTED
- Bob generates a recipe and runs linting gate + self-review before handing to Richard
- Richard reads recipe + project-standards on every review

---

## Step 0 — Evaluate your current configuration

Before touching anything, read what already exists in this project:

- Read `ARCHITECT.md` — note any custom persona, workflow rules, or anti-drift rules the Project Owner has added.
- Read `BUILDER.md` — note any custom coding standards, escalation rules, or build process changes.
- Read `REVIEWER.md` — note any custom review criteria or feedback format changes.
- Check if `team-config.json` already exists — if so, this project may already be partially updated. Skip steps that are already done.
- Check if `project-standards.json` already exists — if so, do not overwrite it.
- Check if `handoff/known-gaps.json`, `handoff/build-recipe.json`, `handoff/sprint-plan.json` already exist — skip those copy steps if they do.

**Rule:** This upgrade adds structure. It does not replace decisions. If the Project Owner has customized how Bob works or what Richard reviews — those customizations survive. You are adding new capabilities around what already exists, not starting over.

When in doubt about any step — stop and confirm with the Project Owner before proceeding.

Run these from the install directory. Replace `[project]` with the project root path.

```bash

cp templates/project-folder/team-config.json [project]/
```

If `[project]/handoff/` does not exist, create it first:
```bash

```

## Step 3 — Fill team-config.json

Open `[project]/team-config.json`. Ask the Project Owner:

1. **Team names** — What are your agent names? (defaults: Arch, Bob, Richard)
2. **Models** — Does each agent have a specific model? (null = uses active session model)
3. **RTK** — Is RTK installed? (true/false)
4. **Project name and stack** — What is this project called and what stack does it use?
5. **Context file** — What is your project context file called? (default: CLAUDE.md)

Fill in every field. Example of a completed config:

```json
{
  "version": "1.3.0",
  "install": "per-project",
  "team": {
    "architect": { "name": "Arch", "model": "claude-opus-4-7" },
    "builder":   { "name": "Bob",  "model": "claude-sonnet-4-6" },
    "reviewer":  { "name": "Richard", "model": "claude-haiku-4-5-20251001" }
  },
  "project": {
    "name": "My Project",
    "stack": "WordPress",
    "context_file": "CLAUDE.md"
  },
  "rtk": true
}
```

## Step 5 — Update ARCHITECT.md

Make the following changes to `[project]/ARCHITECT.md`:

**Replace the Session Start section** with the v1.3.0 version. The new session start reads `team-config.json` first, does a JSON-to-JSON version check, reads `known-gaps.json`, reads `sprint-plan.json`. Copy it exactly from the installed template:

```
cat [install-dir]/templates/project-folder/ARCHITECT.md
```

Extract the Session Start section (lines 6–20 approximately) and paste it into the project's ARCHITECT.md, preserving the existing persona and other sections.

Also add these two new sections if they don't exist. Insert after the "Briefing Richard" section:

**Sprint Planning section:**
```
## Sprint Planning

Before any work starts, write `handoff/sprint-plan.json`:

{
  "sprint": 1,
  "goal": "[What this sprint delivers]",
  "steps": [
    { "n": 1, "description": "[Step description]", "status": "pending" }
  ],
  "current_step": 1,
  "blocked": null
}

Update `current_step` and step `status` as work progresses. Bob and Richard read this to understand where each step fits.
```

**Known Gaps section:**
```
## Known Gaps

When any agent flags out-of-scope work, add it to `handoff/known-gaps.json`:

{
  "id": "KG-N",
  "description": "[What was deferred and why]",
  "flagged_in_step": N,
  "flagged_by": "[Arch|Bob|Richard]",
  "status": "open",
  "target_step": null
}

Review open gaps at every session start. Nothing falls through.
```

**Update the Deploy Gate** — add two steps at the end:
```
8. Update `handoff/sprint-plan.json` — mark step complete, advance `current_step`.
9. Update `handoff/known-gaps.json` — add any new gaps flagged during this step.
```

**Update Anti-Drift Rules** — replace:
```
Out-of-scope items → handoff/BUILD-LOG.md Known Gaps.
```
with:
```
Out-of-scope items → `handoff/known-gaps.json`. Do not expand the step.
```
